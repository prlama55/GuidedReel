# @guidedreel/core and the dependency rules

`packages/core` is a thin umbrella; apps (`apps/web`, `apps/desktop`, and every app generated by `create-guidedreel`) depend on it and nothing else from the engine.

| Subpath                       | Re-exports                            | Runs in                              |
| ----------------------------- | ------------------------------------- | ------------------------------------ |
| `@guidedreel/core`            | `schema` + `engine` + `templates`     | anywhere (no React, no Node)         |
| `@guidedreel/core/ui`         | `ui` (editor, pages, store, Player)   | browser / Electron renderer          |
| `@guidedreel/core/render`     | `renderer` (LocalRemotionRenderer…)   | Node: Next API routes, Electron main |
| `@guidedreel/core/storage`    | `storage`                             | per implementation                   |
| `@guidedreel/core/providers`  | `providers` (cloud TTS)               | Node or browser                      |
| `@guidedreel/core/styles.css` | `@import "@guidedreel/ui/styles.css"` | app stylesheet                       |

Files: `packages/core/src/{index,ui,render,storage,providers}.ts` are one-line `export *`; `src/styles.css`; `tsup.config.ts` copies the CSS. `export *` from several packages fails typecheck (TS2308) if two packages export the same name — rename at the source.

## Dependency policy

- `react` / `react-dom`: **peerDependencies** of `ui`, `compositions`, `core` (devDependencies for tests). Apps list them as real `dependencies` (desktop too: electron-builder packs only `dependencies`, and `remotion` requires React in the main process).
- `remotion`, `@remotion/*`: **regular dependencies** of `compositions`, `ui` (`@remotion/player`), `renderer`. Never in an app manifest. Single exact version in the catalog.
- Workspace deps use `workspace:*`; pnpm rewrites `workspace:`/`catalog:` on publish.
- Graph: `apps → core → {ui → compositions → engine → schema; templates → engine; storage → engine; renderer → compositions/metadata + engine; providers}`.

## How the apps load it

- **Next.js** (`apps/web/next.config.ts`): no `transpilePackages` (dist is JS). `serverExternalPackages` lists `@guidedreel/renderer`, `@guidedreel/compositions`, `@remotion/renderer`, `@remotion/bundler`, compositor binaries, `esbuild`, `webpack`. Reason: tsup strips the `/* turbopackIgnore */` comment on `require.resolve('@guidedreel/compositions/entry')`, so the renderer must stay outside the server bundle and load from `node_modules`.
- **Electron main** (`apps/desktop/electron.vite.config.ts`): `externalizeDepsPlugin()` externalizes every dependency; Electron 44 (Node 24) `require()`s the ESM `dist` at runtime (no top-level await allowed in packages). The renderer process bundles `core/ui` with Vite.
- Shells register extra templates with `templateRegistry.registerAll(...)` (engine `TemplateRegistry`; replaces duplicate ids so HMR re-runs are safe).

## Adding something to core

1. Implement it in the right package (see [[scenes-and-templates]], [[render-pipeline]]).
2. Export it from that package's `src/index.ts`; core picks it up through `export *`. Only add a new core subpath for a new runtime boundary (e.g. a Node-only area).
3. `pnpm build:packages && pnpm typecheck`. Add a changeset ([[release-publishing]]).
